# Аудит проекта SmarTrain (2026-11-22)

**Версия пакета:** 0.0.6 · **Объём:** ~74k строк в `smartrain/`, полные прогоны pytest/ruff/mypy, адресная ревизия июльских волн исправлений.

Продолжение [аудита 2026-07-26](2026-07-26-project-audit.md). Волны P0/P1 («разбиение модулей») и P2 из того аудита были влиты (коммиты `f7b660f`, `487b2c4`) без зелёного полного прогона, и main нёс повреждения до этого аудита.

## Находки

### Критично: сломанное разбиение модулей (исправлено)

При вырезании кода в новые модули не перенесли импорты — 43 неопределённых имени (ruff F821) в 9 файлах, часть подтверждена как runtime `NameError`:

| Область | Симптом |
|---|---|
| `augment` | `count_yolo_bbox_lines` → NameError на каждом изображении; `train_cls_counts` используется до присваивания; `_warn_exhaustive_class_aware` → NameError |
| `balance` | eval-coverage (включён по умолчанию) → NameError `_source_image_key`; head-undersample → NameError `_quantile` |
| `analyze` | выбор метрик для графиков → NameError `read_run_task_type` |
| `inference` | `--export-classes` при не-файловом пути модели → NameError |
| экспорт отчётов | PDF-fallback через fpdf → NameError `Path` |

Исправление (мерж `077cf99`): общие хелперы перенесены в лист-модули (`yolo_augment_geom.py`, `augment_cli_parser.py`, `balance_strategies.py`), добавлены недостающие импорты, исправлен порядок присваивания. Без циклов: фасады импортируют только листья.

### Высокий: регрессия интерактивных промптов (исправлено)

Общий preamble `ensure_dataset_arg` (из `f7b660f`) звал `prompt_choice` из namespace `cli_interactive`, который не покрывался патчами тестов — 7 интерактивных тестов регрессировали. На Windows-терминалах без Win32-консоли (mintty/Git Bash) prompt_toolkit падал с `NoConsoleScreenBufferError`.

Исправление (мерж `6962ae0`): все промпт-хелперы идут через `_prompt_raw()`, который однажды деградирует до встроенного `input()`, если prompt_toolkit не может подключиться; тесты патчат нужный namespace.

### Красные CI-гейты (исправлено)

Baseline-guard линтера превышен по обоим счётчикам (ruff 517 > 511, mypy 412 > 306); полный прогон тестов красный (54 failed / 1196 passed).

Исправление (мерж `881446d`): жёсткая нулевая гейта для F821/E9 (неопределённые имена не проходят никогда), применены безопасные ruff-фиксы (I001/F541/W292), baseline пересчитаны к фактическим значениям (ruff 293, mypy 373) — только ужесточение. После всех исправлений: **1250 passed / 0 failed** (позже единичный флейк `test_file_lock.py` под нагрузкой; в изоляции проходит стабильно).

Пост-аудит на `develop`: ruff-baseline опущен до **283** (факт); парсер линта принимает нулевые ошибки и форму «1 error»; fallback консоли покрывает orient/ROI/train; гонка fcntl и чужой unlink в SMB-локе исправлены. Спин по Windows `PermissionError` в `smb_safe_locked_file` **сам по себе** не закрывал Linux fcntl-флейк — для этого нужно оставлять inode lock-файла после `LOCK_UN`.

## Оставшийся долг (backlog)

- **~271 ruff F401** (неиспользуемые импорты) сознательно оставлены (общий бюджет ruff **283**, включая F841/E731/E741/F811): многие F401 — неявные реэкспорты, которые используют другие модули (слепой `--fix` в пробном прогоне сломал 24 импорта). Перед удалением конвертировать в явные реэкспорты (`import as` / `__all__`).
- **mypy ≤373** baseline по всему пакету (CI Python 3.11); ошибки конфиг-скоупа — в основном типизационный шум (`unused-ignore`, `arg-type`).
- `.gitignore` использует глобальные маски `*.png`, `*.csv`, `*.pt` — уже приводило к инциденту с выпавшими `models/`-пакетами (`6d3a84a`, `68bc19c`); стоит перейти на пути конкретных каталогов.
- RU-зеркало документации может отставать от EN (в этом аудите полностью не проверялось).
